# Security policy

## Supported version

Security fixes are applied to the current `main` branch.

## Reporting a vulnerability

Do not open a public issue containing credentials, personal information, or exploit details. Report a suspected vulnerability privately to `shivayogih72@gmail.com` with:

- the affected route, file, dependency, or workflow;
- clear reproduction steps;
- expected and observed behaviour;
- impact and any suggested mitigation.

Please allow reasonable time for investigation before public disclosure.

## Repository safety

Never commit API keys, tokens, client-confidential material, private repository metadata, internal screenshots, or personal documents. The website is a static export and does not require runtime secrets.
