# Contributing

Thank you for helping improve this portfolio.

## Before opening a change

- Keep personal facts and project claims consistent with `docs/content-guide.md`.
- Do not add confidential client information or unverified public links.
- Prefer typed content updates over copy embedded in presentation components.
- Preserve static-export and `/shivayogi-portfolio/` compatibility.
- Keep client-side JavaScript focused and accessible.

## Development

```bash
npm ci
npm run dev
```

Before requesting review:

```bash
npm run verify
```

Use focused conventional commits such as `feat:`, `fix:`, `test:`, `docs:`, `ci:`, and `chore:`. Pull requests should explain the user-facing change, validation performed, accessibility impact, and any content verification source.
